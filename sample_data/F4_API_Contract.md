# F4 — File Upload API Contract

## 1. Назначение

API предназначен для загрузки CSV- и JSON-файлов в систему Data Quality Analyzer.

Backend принимает файл, проверяет его, читает данные, сохраняет датасет и возвращает его метаданные.

## 2. Endpoint

`POST /api/datasets`

Тип запроса: `multipart/form-data`.

Поля запроса:

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `file` | File | Да | CSV- или JSON-файл |
| `name` | string | Да | Название датасета |

Пример:

```http
POST /api/datasets
Content-Type: multipart/form-data
```

## 3. Ограничения

- Форматы: CSV, JSON.
- Максимальный размер: 20 МБ.
- Максимальное количество строк: 100 000.
- CSV: кодировка UTF-8-sig, резервная cp1251.
- CSV: разделители `,` или `;`.
- JSON: массив объектов.

Пустые файлы, некорректный JSON, некорректный CSV и неподдерживаемые форматы отклоняются.

## 4. Успешный ответ

HTTP `201 Created`

```json
{
  "id": 1,
  "name": "Продажи за месяц",
  "source_type": "csv",
  "row_count": 1500,
  "columns": [
    "product",
    "price",
    "quantity"
  ]
}
```

Описание полей:

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | ID датасета |
| `name` | string | Название датасета |
| `source_type` | string | `csv` или `json` |
| `row_count` | integer | Количество строк |
| `columns` | array of strings | Названия столбцов |

## 5. Ошибки

Все ошибки возвращаются в общем формате проекта.

### Некорректный файл или данные

HTTP `400 Bad Request`

```json
{
  "error": {
    "code": "validation_error",
    "message": "Invalid file or dataset"
  }
}
```

### Превышен размер файла

HTTP `413 Payload Too Large`

```json
{
  "error": {
    "code": "file_too_large",
    "message": "File size exceeds 20 MB"
  }
}
```

### Превышено количество строк

HTTP `400 Bad Request`

```json
{
  "error": {
    "code": "row_limit_exceeded",
    "message": "Dataset exceeds 100000 rows"
  }
}
```

## 6. Сохранение данных

После успешной загрузки Backend:

1. Проверяет файл.
2. Определяет формат.
3. Читает данные.
4. Проверяет количество строк.
5. Сохраняет данные в `data/uploads/{id}.pkl`.
6. Сохраняет метаданные в таблицу `datasets`.
7. Создаёт событие в таблице `events`.

Метаданные датасета должны содержать:
- `id`;
- `name`;
- `original_filename`;
- `source_type`;
- `file_path`;
- `row_count`;
- `columns_json`;
- `created_at`.

## 7. Границы F4

В F4 не входят:
- предпросмотр строк датасета;
- проверка качества данных;
- поиск пропусков и дубликатов;
- пользовательские правила;
- графики и отчёты;
- экспорт.

Эти функции реализуются отдельно.

## 8. Связь с другими функциями

F4 создаёт датасет, который в дальнейшем используется другими функциями кейса №5.

F4 не должен реализовывать функциональность следующих этапов самостоятельно.
