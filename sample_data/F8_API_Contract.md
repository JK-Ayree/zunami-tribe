# F8 — Alert Rules API Contract

## 1. Назначение

API предназначен для управления правилами мониторинга хостов.

Пользователь может:
- создавать правила;
- получать список правил;
- редактировать правила;
- удалять правила.

На этом этапе API не проверяет метрики и не создаёт уведомления.

## 2. Поля правила

| Поле | Тип | Описание |
|---|---|---|
| `id` | integer | ID правила |
| `name` | string | Название правила |
| `host_id` | integer или null | ID хоста. `null` означает все хосты |
| `metric` | string | Контролируемая метрика |
| `operator` | string | Условие сравнения |
| `threshold` | number | Пороговое значение от 0 до 100 |
| `severity` | string | Важность правила |
| `is_enabled` | boolean | Включено ли правило |

## 3. Допустимые значения

### metric

- `cpu_percent` — загрузка CPU;
- `ram_percent` — использование RAM;
- `disk_percent` — использование диска.

### operator

- `>` — больше;
- `<` — меньше.

### severity

- `low` — низкая;
- `medium` — средняя;
- `high` — высокая.

### host_id

- Числовой ID существующего хоста.
- `null` — правило применяется ко всем хостам.

Пороговое значение должно быть числом от 0 до 100 включительно.

## 4. Создание правила

`POST /api/alert-rules`

Тело запроса:

```json
{
  "name": "Высокая загрузка CPU",
  "host_id": null,
  "metric": "cpu_percent",
  "operator": ">",
  "threshold": 80,
  "severity": "high"
}
```

Успешный ответ: HTTP `201 Created`

```json
{
  "id": 1,
  "name": "Высокая загрузка CPU",
  "host_id": null,
  "metric": "cpu_percent",
  "operator": ">",
  "threshold": 80,
  "severity": "high",
  "is_enabled": true
}
```

`is_enabled` автоматически устанавливается в `true` при создании.

## 5. Получение списка правил

`GET /api/alert-rules`

Успешный ответ: HTTP `200 OK`

```json
{
  "items": [
    {
      "id": 1,
      "name": "Высокая загрузка CPU",
      "host_id": null,
      "metric": "cpu_percent",
      "operator": ">",
      "threshold": 80,
      "severity": "high",
      "is_enabled": true
    }
  ],
  "total": 1
}
```

Если правил нет, возвращается пустой массив `items` и `total: 0`.

## 6. Редактирование правила

`PUT /api/alert-rules/{id}`

Тело запроса:

```json
{
  "name": "Критическая загрузка CPU",
  "host_id": 1,
  "metric": "cpu_percent",
  "operator": ">",
  "threshold": 90,
  "severity": "high"
}
```

Успешный ответ: HTTP `200 OK`

Возвращается обновлённый объект правила в том же формате, что и при создании.

## 7. Удаление правила

`DELETE /api/alert-rules/{id}`

Успешный ответ: HTTP `200 OK`

```json
{
  "ok": true
}
```

Если правило с указанным ID не найдено, возвращается HTTP `404 Not Found`.

## 8. Ошибки

Все ошибки возвращаются в общем формате проекта.

### Некорректные данные

HTTP `400 Bad Request`

```json
{
  "error": {
    "code": "validation_error",
    "message": "Invalid alert rule data"
  }
}
```

### Правило или хост не найдены

HTTP `404 Not Found`

```json
{
  "error": {
    "code": "not_found",
    "message": "Resource not found"
  }
}
```

## 9. Работа с базой данных

Используется существующая таблица `alert_rules`.

Каждое правило хранится отдельно и содержит:
- название;
- привязку к хосту или всем хостам;
- метрику;
- оператор сравнения;
- порог;
- важность;
- признак включения.

При создании правила `is_enabled = true`.

В рамках F8 не требуется создавать записи в таблице `alerts`.

## 10. Связь с другими функциями

- F2 предоставляет список зарегистрированных хостов.
- F6 обеспечивает поступление метрик.
- F8 хранит правила, по которым в дальнейшем можно будет проверять метрики.

Автоматическая проверка метрик и создание уведомлений в этот контракт не входят.
