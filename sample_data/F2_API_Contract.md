# F2 — API-контракт: регистрация и список хостов

**Назначение документа**

Этот документ фиксирует единый формат взаимодействия Backend и Frontend в рамках F2. Обе стороны должны ориентироваться на него при разработке.

## 1. Общие соглашения

- Все запросы начинаются с `/api`.
- Формат передачи данных — JSON.
- Названия полей и структура ответов должны совпадать с указанными ниже.
- При возникновении необходимости изменить контракт разработчик сначала согласовывает изменение с тимлидом.

## 2. Регистрация хоста

**POST `/api/hosts`**

Запрос:

```json
{
  "name": "lab-server-01",
  "description": "Учебный стенд 1"
}
```

Успешный ответ — HTTP 201:

```json
{
  "id": 1,
  "name": "lab-server-01",
  "description": "Учебный стенд 1",
  "api_token": "generated_token",
  "status": "unknown",
  "last_seen_at": null
}
```

Важно:
- `name` — обязательное поле.
- `description` — необязательное поле.
- `api_token` генерируется Backend.
- Токен возвращается Frontend после регистрации, чтобы пользователь мог его скопировать.

## 3. Получение списка хостов

**GET `/api/hosts`**

Успешный ответ — HTTP 200:

```json
{
  "items": [
    {
      "id": 1,
      "name": "lab-server-01",
      "status": "unknown",
      "last_seen_at": null,
      "last_metrics": null
    }
  ],
  "total": 1
}
```

Важно:
- `items` — список зарегистрированных хостов.
- `total` — общее количество хостов.
- `last_metrics` — последние технические показатели; если данных пока нет, возвращается `null`.
- `api_token` в списке хостов не возвращается.

## 4. Удаление хоста

**DELETE `/api/hosts/{id}`**

Пример:

`DELETE /api/hosts/1`

Успешный ответ — HTTP 200:

```json
{
  "ok": true
}
```

Если хост с указанным ID не найден, Backend возвращает HTTP 404.

## 5. Обработка ошибок

Ошибки возвращаются в едином формате:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Описание ошибки"
  }
}
```

Основные случаи:
- HTTP 400 — некорректные данные или пустое название.
- HTTP 404 — хост не найден.
- HTTP 409 — хост с таким именем уже существует.

## 6. Ответственность сторон

**Backend:**
- Реализует указанные маршруты.
- Обеспечивает соответствие ответов контракту.
- Обрабатывает ошибки.

**Frontend:**
- Отправляет запросы в указанном формате.
- Использует полученные данные для отображения интерфейса.
- Корректно обрабатывает успешные ответы и ошибки.

**Тимлид:**
- Следит за соблюдением контракта.
- Согласовывает изменения формата запросов и ответов.
- Проверяет совместную работу Frontend и Backend.

---

**Важно:** этот документ определяет формат взаимодействия, а не способ реализации. Внутреннюю структуру кода и технические решения каждая сторона выбирает самостоятельно в рамках своей задачи.
