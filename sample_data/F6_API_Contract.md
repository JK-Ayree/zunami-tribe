# F6 — API Contract

## 1. Назначение

API предназначен для приёма технических показателей компьютера от агента.

Агент отправляет:
- загрузку процессора (CPU);
- использование оперативной памяти (RAM);
- использование диска (Disk);
- время сбора показателей.

Backend определяет хост по API-токену и сохраняет полученные данные.

## 2. Endpoint

`POST /api/ingest`

Назначение: принять один набор показателей от агента.

## 3. Заголовки запроса

```http
Content-Type: application/json
X-Api-Token: a1b2c3...
```

`X-Api-Token` — токен зарегистрированного хоста, полученный при регистрации через F2.

Токен передаётся только в заголовке, не в теле запроса.

## 4. Тело запроса

```json
{
  "cpu_percent": 23.5,
  "ram_percent": 61.0,
  "disk_percent": 44.2,
  "collected_at": "2026-11-27T15:00:00Z"
}
```

Поля:

| Поле | Тип | Описание |
|---|---|---|
| `cpu_percent` | number | Загрузка процессора, от 0 до 100 |
| `ram_percent` | number | Использование оперативной памяти, от 0 до 100 |
| `disk_percent` | number | Использование диска, от 0 до 100 |
| `collected_at` | string | Время сбора показателей в формате ISO 8601 UTC |

Все четыре поля обязательны.

`host_id` в теле запроса не передаётся: Backend определяет хост по API-токену.

## 5. Успешный ответ

HTTP `202 Accepted`

```json
{
  "ok": true
}
```

Ответ означает, что данные приняты и сохранены.

## 6. Ошибки

### Неверный или отсутствующий API-токен

HTTP `401 Unauthorized`

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Invalid API token"
  }
}
```

### Некорректные данные

HTTP `400 Bad Request`

```json
{
  "error": {
    "code": "validation_error",
    "message": "Invalid metrics data"
  }
}
```

Ошибки должны возвращаться в общем формате проекта.

## 7. Действия Backend после получения запроса

1. Проверить API-токен.
2. Найти соответствующий хост в таблице `hosts`.
3. Проверить полученные показатели.
4. Сохранить показатели в таблицу `metrics`.
5. Обновить `hosts.last_seen_at`.
6. Установить `hosts.status = 'online'`.

## 8. Таблица metrics

Для хранения показателей используется таблица `metrics`.

| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER | Первичный ключ |
| `host_id` | INTEGER | ID хоста, внешний ключ на `hosts.id` |
| `cpu_percent` | REAL | Загрузка CPU |
| `ram_percent` | REAL | Использование RAM |
| `disk_percent` | REAL | Использование диска |
| `collected_at` | TEXT | Время сбора показателей |

Каждая успешно принятая отправка создаёт одну запись.

## 9. Частота отправки

Агент отправляет показатели каждые 10 секунд.

При сетевой ошибке агент не должен аварийно завершаться. Следующая попытка выполняется в следующем цикле отправки.

## 10. Границы F6

В рамках первой версии не реализуются:
- графики;
- аналитика и агрегация;
- уведомления;
- автоматическое определение статуса offline;
- очередь метрик при отсутствии сети;
- настройка интервала отправки.

## 11. Связь с F2

F6 использует зарегистрированные в F2 хосты и их API-токены.

F6 не создаёт и не регистрирует хосты самостоятельно.
