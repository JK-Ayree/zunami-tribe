# F5 — Data Table API Contract

## 1. Назначение

API предназначен для просмотра строк ранее загруженного датасета.

Поддерживаются:
- получение строк;
- пагинация;
- сортировка;
- фильтрация.

Все операции выполняются на Backend. Frontend получает только текущую страницу данных.

## 2. Получение строк датасета

`GET /api/datasets/{id}/rows`

### Параметры запроса

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `page` | integer | Нет | Номер страницы, по умолчанию 1 |
| `page_size` | integer | Нет | Количество строк: 25, 50 или 100. По умолчанию 50 |
| `sort_by` | string | Нет | Название столбца для сортировки |
| `sort_dir` | string | Нет | Направление: `asc` или `desc` |
| `filter_col` | string | Нет | Название столбца для фильтрации |
| `filter_value` | string | Нет | Значение для поиска |

Пример:

`GET /api/datasets/1/rows?page=1&page_size=50&sort_by=age&sort_dir=asc&filter_col=city&filter_value=Moscow`

## 3. Правила фильтрации и сортировки

### Фильтрация

- Работает по одному выбранному столбцу.
- Используется принцип «содержит».
- Поиск текста выполняется без учёта регистра.
- Если фильтр не задан, возвращаются все строки датасета.

### Сортировка

- Сортировка выполняется по одному столбцу.
- `asc` — по возрастанию.
- `desc` — по убыванию.
- Если сортировка не задана, используется исходный порядок строк.

### Пагинация

- Нумерация страниц начинается с 1.
- Размер страницы: 25, 50 или 100 строк.
- Сначала применяется фильтрация, затем сортировка, затем пагинация.
- `total` показывает количество строк после фильтрации, но до пагинации.

## 4. Успешный ответ

HTTP `200 OK`

```json
{
  "columns": ["name", "age", "city"],
  "rows": [
    {
      "name": "Alex",
      "age": 25,
      "city": "Moscow"
    },
    {
      "name": "Maria",
      "age": 30,
      "city": "Moscow"
    }
  ],
  "page": 1,
  "page_size": 50,
  "total": 2
}
```

### Описание полей ответа

| Поле | Тип | Описание |
|---|---|---|
| `columns` | array | Названия столбцов датасета |
| `rows` | array | Строки текущей страницы |
| `page` | integer | Текущая страница |
| `page_size` | integer | Размер страницы |
| `total` | integer | Общее количество строк после фильтрации |

Пустые значения и `NaN` должны передаваться как `null`, чтобы ответ оставался корректным JSON.

Если по фильтру ничего не найдено, возвращается пустой массив `rows` и `total: 0`.

## 5. Ошибки

### Датасет не найден

HTTP `404 Not Found`

```json
{
  "error": {
    "code": "not_found",
    "message": "Dataset not found"
  }
}
```

### Некорректные параметры

HTTP `400 Bad Request`

```json
{
  "error": {
    "code": "validation_error",
    "message": "Invalid query parameters"
  }
}
```

К некорректным параметрам относятся:
- отрицательный номер страницы;
- недопустимый размер страницы;
- неизвестное направление сортировки;
- отсутствующий в датасете столбец сортировки или фильтрации.

Все ошибки возвращаются в общем формате проекта.

## 6. Получение списка датасетов

Для выбора датасета Frontend использует существующий endpoint:

`GET /api/datasets`

Он относится к функциональности загрузки и хранения датасетов, а не к реализации F5.

F5 не должен повторно реализовывать этот endpoint.

## 7. Ограничения F5

В рамках первой версии не реализуются:
- редактирование данных;
- удаление строк;
- сложные фильтры;
- фильтрация по диапазонам;
- экспорт;
- поиск по смыслу;
- аналитика и визуализация.

## 8. Общий принцип

Backend выполняет фильтрацию, сортировку и пагинацию.

Frontend отображает полученные данные и отправляет новые запросы при изменении параметров таблицы.

Передача всего датасета на Frontend запрещена.
